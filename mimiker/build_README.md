# Mimikerビルドシステム

## どのように機能するのか？

- 次の標準ターゲットが定義されています: download, install, build, clean,
  distclean,  format
- 標準ターゲットのいずれかを満たすには、SUBDIRにリストされているすべての
  ディレクトリで標準ターゲットと同じターゲットを最初に満たす必要があります
  （深さ優先探索）。この規則の唯一の例外はformatターゲットで、このターゲット
  ではFORMAT-RECURSEが未定義の場合だけ再帰が適用されます。
- SUBDIRにリストされた各ディレクトリに対して、特別な`subdir`-beforeターゲットを
  指定することができます。そのようなターゲットが存在する場合はそのサブ
  ディレクトリのbuildターゲットを実行する前にそのターゲットが実行されます。
- 共通makefileをインクルードするmakefileではサブディレクトリで`標準ターゲット`が
  満たされた後に実行する`標準ターゲット`-hereターゲットを定義することができます。
- すべてのmakefileを通じてTOPDIR変数が使用されます。TOPDIR変数が使用される場合は
  共通makefileをインクルードするmakefileは常にこの変数にホストシステムのmimiker
  ディレクトリパスを設定する必要があります。
- buildディレクトリのmakefileのAPIを構成するすべてのmake変数はmakefileを
  インクルードする前にこのmakefileをインクルードするmakefileによって設定される
  必要があります。

### makefile間のインタフェース

buildディレクトリにあるmakefileは他のmakefileからインクルードすることが
できます。各makefileはこれをインクルードするmakefileが設定する一連のmake変数を
定義します。これらの変数と簡単な説明が各makefileの冒頭で提供されています。
変数がデフォルト値を持つ場合や他の変数がその使用に条件を設けている場合、
その変数はオプションです。そうでない場合、その変数はこのmakefileをインクルード
するmakefileで設定する必要があります。この場合、設定はmakefileをインクルード
する前に行う必要があります。ビルドシステムを構成するmakefileを通じて特別な
make変数であるTOPDIRが使用されます。トップレベルのmakefileは常にこの変数に
ホストシステムのmimikerディレクトリへのパスを設定する必要があります。


### コマンドライン変数

`make`のコマンドラインでは次の変数を指定することができます。

- BOARD: ターゲットボード。現在サポートされているボードは`malta`と`rpi3`で
  デフォルトは`malta`です。
- VERBOSE: 1: 多くを出力、それ以外: 出力しない。
- KASAN: 1: カーネルアドレスサニタイザを使用する。それ以外: 使用しない。
  デフォルトは0です。
- LOCKDEP: 1: ロック依存性バリデータを使用する。それ以外: 使用しない。
  デフォルトは0です。
- CLANG: 1: Clangを使用、それ以外: GCCを使用。

### 共通変数

次のmake変数が共通makefileをインクルードするmakefileによって設定されます。

- SOURCES: コンパイルするソースファイル(C、アセンブラ、Yaccなど)
- BINDIR: プログラムをインストールする $(SYSROOT) からの相対パス。
- BINMODE: mainファイルがインストールされるパーミッション。
- BUILD-FILES: 現在の再帰レベルでビルドするファイル。
- INSTALL-FILES: 現在の再帰レベルでインストールするファイル。
- CLEAN-FILES: 現在の再帰レベルで削除するファイル。
- FORMAT-EXCLUDE: フォーマットすべきでないファイル。
- FORMAT-RECURSE: SUBDIRに再帰を適用しない場合は "no"に設定する。それ以外は未定義。
- PHONY-TARGETS: phonyターゲット。
- DEPENDENCY-FILES: 依存関係を指定するファイル(*.Dファイルなど)。
